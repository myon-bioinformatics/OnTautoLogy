# 方針ルール（たたき台）

これは実装ではなく、設計のメモです。ルールの文言も役割分担も、見直し前提の草案です。気づいた点があれば、この文書を直してください。

## 目的

プルリクエストだけで「リポジトリのあり方」を管理すると、限界があります。いま起きていること（事実）と、「こうあるべき」（ルール）が、別々の場所に散らばりやすいからです。

そこで、リポジトリのあり方をオントロジー／ナレッジグラフの事実とルールとして書き、OnTautoLogy（OTL）が次を返すようにします。

- ルール違反
- 次に取るアクション
- その根拠（証拠へのリンク）
- 依存順（`graphlib` による順序付け）

## ルール（案）

対象や数値は暫定です。適用範囲（全リポジトリか、一部か）もまだ決めていません。

### 1. PR 削減

`main` 向けのオープン PR は、同時に最大 1 本にします。それ以外のオープン PR は、次のいずれかに分類し、マージしやすい順に並べます。

- すぐマージ可（CI が緑で、競合がない）
- 競合解消が必要
- 重複なのでクローズ候補

最終目標は、オープン PR をゼロにすることです。

### 2. HTML は 1 つ

HTML / CSS / JS のファイルがリポジトリに乱立しないようにします。対象ファイルの数は 1 以下です。恒常ファイルとして置かず、Python でラップして実行時に生成する方式でも構いません。

### 3. 命名

機能名、ファイル名、コマンド名は、リポジトリ名の小文字に揃えます（既存方針）。ズレがあれば指摘します。ファイル数の削減も、このルールの対象です。

### 4. ワークフロー

`workflow_dispatch`（手動実行）は置きません。GitHub Actions はフル SHA でピンします（既存方針）。

### 5. ナノ環境化

使っている関数だけに絞った最小構成にできる候補を挙げます。例: `numpy_min.py` のような、必要な関数だけを残したモジュールや、必要最小限の apt パッケージだけを入れる構成です。

### 6. お手本

同じルールをすでに満たしている他リポジトリがあれば、そのやり方へのリンクを示し、真似できるようにします。

## 役割分担

| 担当 | 役割 |
| --- | --- |
| 親リポジトリ（myon-bioinformatics） | GitHub から PR、CI、ファイル一覧、ワークフロー定義を取得し、事実として記録する（GitHub 寄り） |
| OTL（OnTautoLogy） | 事実とルールをグラフ化し、違反・次アクション・依存順を、根拠リンク付きで返す（汎用。`graphlib` を使う） |
| PSWB | 表示 UI |

OTL は GitHub への書き込みやマージを行いません。取得も親リポジトリ側です。

## ガードレール

OTL が出すのは候補までです。マージやクローズなどの実行判断は、myon の明示的な承認が必要です。
